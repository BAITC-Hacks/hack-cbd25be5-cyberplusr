# Минимальный OpenAI-агент

В интерфейсе появилась кнопка «ИИ-помощник». Агент выбирает инструменты get_account, get_neighbors и get_priority, читает локальный граф и отвечает со ссылками на счета. Это интеграция с моделью, а не шаблонный ответ по ключевым словам.

## Подключение

В корне проекта скопируйте .env.example в .env (существующий .env не перезаписывайте). Откройте .env в VS Code и заполните:

```dotenv
OPENAI_API_KEY=ваш_ключ_OpenAI_API
OPENAI_MODEL=gpt-4.1-mini
```

Ключ берётся в вашем OpenAI API-проекте. Не вставляйте его в чат или файлы src/. .env исключён из Git. Переменные окружения имеют приоритет над .env. Модель можно заменить на доступную в вашем API-проекте с поддержкой Responses, function calling и structured outputs. Подписка ChatGPT не заменяет настройку доступа и баланса API.

Из PowerShell в папке проекта:

```powershell
.\.venv\Scripts\python.exe run.py --port 5176
```

Если старый сервер занимает порт, остановите его через Ctrl+C либо используйте --port 5177. Откройте адрес, напечатанный сервером. При уже рассчитанном графе и собранном интерфейсе можно запускать быстрее:

```powershell
.\.venv\Scripts\python.exe agent_server.py --port 5176
```

Простой Vite dev-сервер и обычный python -m http.server не обслуживают API агента. Используйте run.py. После изменения .env нажмите «Проверить подключение»: это проверка наличия настройки, а не платный API-запрос. Первый отправленный вопрос проверит доступ к OpenAI.

## Данные и поведение

Перед отправкой нужно включить разрешение в чате: в OpenAI уходят вопрос, выбранный ID и результаты вызванных инструментов — ID, роли, суммы, оценки и связи. Весь Parquet не загружается. Используйте реальные данные только при наличии права на такую передачу; синтетический набор подходит для демонстрации. Запросы платные согласно условиям API-проекта.

Ключ остаётся на Python-сервере, статические файлы раздаются только из dist/. Никогда не копируйте .env в public/ или dist/. API принимает только same-origin localhost-запросы; сервер слушает 127.0.0.1. Он рассчитан на одного локального пользователя, а не публичное размещение.

Каждый вопрос независим, история переписки в модель не пересылается и хранится только в состоянии страницы. На вопрос допускается до пяти запросов модели и четырёх вызовов инструментов, не более 20 рёбер за один вызов и пяти счетов из очереди. Ограничение результатов явно передаётся модели. Повторных автоматических запросов после ошибки нет. Responses вызывается с store=false; это не обещание полного отсутствия хранения провайдером.

Ответ содержит текст и проверенные ссылки. Сервер отклоняет ссылки на ID, которых не было в результатах инструментов. Это не гарантирует истинность всего текста: объяснения и численные утверждения всё равно проверяет аналитик. Агент не меняет роли, не блокирует счета, не пишет файлы и не исполняет код.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_agent test_pipeline
npm.cmd run build
```

test_agent использует синтетический граф и подставной ответ API: проверяет цикл инструментов, направления, ограничение выборки, ссылки, лимит шагов, запрет отправки без согласия, чужой Origin и недоступность .env через HTTP. Эти тесты не проверяют качество реальной модели или доступность вашего API-ключа.

Основа реализации: [официальная документация function calling](https://developers.openai.com/api/docs/guides/function-calling) и [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).
